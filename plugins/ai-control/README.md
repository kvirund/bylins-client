# Плагин ai-control — управление сессиями ИИ

Даёт внешним ИИ-агентам управляемый доступ к игре: свой контекст на агента,
чтение вывода «с прошлого раза», отправка команд с ожиданием ответа и —
с явного разрешения игрока — управление самим клиентом.

## Устройство

```
ИИ-агент  ──MCP(stdio)──>  mcp/bylins_mcp.py  ──HTTP(127.0.0.1)──>  плагин  ──>  PluginAPI  ──>  клиент
```

Два слоя нужны, чтобы не тащить MCP-SDK в Kotlin: плагин отдаёт обычный
HTTP+JSON (отлаживается `curl`), а тонкий мост переводит его в MCP.

## Установка

1. Собрать плагин и положить JAR в папку плагинов клиента:

```bash
./gradlew :plugins:ai-control:buildPlugin
```

2. В клиенте на вкладке **Плагины** включить «Управление ИИ» и **выдать разрешения**:
   - `Локальный сетевой порт` — иначе сервер не стартует;
   - `Управление клиентом` — профили, триггеры, алиасы, хоткеи, вкладки;
   - `Управление подключением` — connect/disconnect.

   Разрешения проверяются на каждом вызове: отзыв действует немедленно.

3. Сервер поднимается сам после выдачи разрешения. Узнать мастер-токен:

```
#ai token
```

Остановить/поднять вручную — `#ai stop` / `#ai start` или кнопка в правой панели.

## Подключение ИИ (MCP)

Зарегистрировать мост как MCP-сервер (пример для Claude Code):

```bash
claude mcp add bylins-mud -- python C:/dev/games/bylins-client/plugins/ai-control/mcp/bylins_mcp.py
```

Переменные окружения моста:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BYLINS_AI_URL` | адрес плагина | `http://127.0.0.1:4747` |
| `BYLINS_AI_MASTER_TOKEN` | токен из `#ai token` | — (обязателен) |
| `BYLINS_AI_NAME` | имя контекста в списке игрока | `claude` |

### Инструменты

| Инструмент | Что делает |
|---|---|
| `mud_read` | новый вывод с прошлого чтения (курсор двигается сам) |
| `mud_exec` | отправить команды и дождаться ответа |
| `mud_status` | подключение, журнал, список контекстов |
| `mud_client` | управление клиентом (`action` + `params`) |
| | профили, соединение, триггеры/алиасы/хоткеи, вкладки, **настройки и логи** |
| `mud_map` | карта: текущая комната, поиск, маршрут, заметки, поля и свойства комнат |
| | `mud_client` c `action: "msdp"` — структурированные данные сервера |
| `mud_take_lease` | запросить право отправки команд (если держатель молчит) |
| `mud_close` | закрыть контекст и снять его триггеры |

### Коды ответов HTTP

| Код | Значение |
|---|---|
| 200 | успех |
| 401 | нет/неверный токен, либо сессия закрыта по таймауту — откройте заново |
| 403 | пользователь не выдал нужное разрешение (в теле — какое именно) |
| 409 | право отправки команд у другой сессии, либо сессия заглушена игроком |
| 403 | нет права на запись — в тексте указано, какая сессия его держит |
| 404 | сущность не найдена (в тексте — что именно и с каким id) |
| 400 | не хватает обязательного параметра |

Мутирующие вызовы (`*/create`, `*/update`, `*/delete`, `connect`, изменения
карты) требуют права записи и отвечают понятной ошибкой, а не `{"ok":false}`:
по нему нельзя было отличить «нет прав» от «неверный id».

## Команды игрока

```
#ai status        состояние сервера и сессий
#ai list          кто подключён, что делает
#ai start | stop  запустить/остановить сервер
#ai token         показать мастер-токен
#ai kick <id>     закрыть контекст (снимает его триггеры)
#ai mute <id>     запретить/разрешить агенту слать команды
#ai take <id>     передать право отправки команд
```

Все действия агентов пишутся во вкладку вывода **«ИИ»**.

## Ключевые решения

**Владение ресурсами.** Триггеры и таймеры, созданные агентом, принадлежат его
сессии. Закрытие контекста — вручную, по таймауту простоя (5 минут) или при
остановке сервера — снимает их разом, поэтому «мёртвых» триггеров не остаётся.

**Курсор вместо «дай весь буфер».** У журнала монотонные номера строк, они не
сбрасываются при вытеснении. Агент всегда получает только новое, а если отстал
и часть строк выпала — видит `missed > 0` и понимает, что картина неполная.

**Одна пишущая сессия.** Право отправлять команды держит один агент (lease),
иначе несколько ИИ перебивают друг друга. Первый подключившийся получает его
автоматически; игрок может передать (`#ai take`) или заглушить (`#ai mute`).
Агент может запросить право сам (`mud_take_lease`) — оно отдаётся, только если
текущий держатель молчит дольше 30 секунд, поэтому «живого» агента не перебить.

**Поля комнаты правятся отдельно от свойств.** `property/set` пишет
произвольные key/value, но на отрисовку карты влияют поля самой комнаты, и
своим `explored=true` её посещённой не сделать. Поэтому есть `room/set`:
`name`, `zone`, `terrain`, `visited`, `notes`, `color`. Так подписывают
комнаты-заготовки (известны только по выходу соседа, имя и зона пустые) и
закрывают места, куда заходить нельзя — ДТ помечается посещённой, не убивая
персонажа ради галочки на карте. Пустая строка очищает поле.

**Панель игрока.** Плагин регистрирует блок в правой панели: состояние сервера,
список агентов и кнопки «Отключить», «Заглушить», «Перо» напротив каждого.

**Ожидание по «тишине».** `mud_exec` возвращается, когда вывод перестал идти
(~400 мс) или истёк таймаут. Это надёжнее подсчёта строк и не требует
детектора промпта; при необходимости точность можно поднять, вынеся
`PromptDetector` из плагина-ассистента в общий код.

**Безопасность.** Сервер слушает только `127.0.0.1`, мастер-токен нужен для
открытия контекста, у каждой сессии свой токен. Сервер поднимается
автоматически при включении плагина — но только если выдано право на порт.
Наружу порт выставлять нельзя — это управление вашим персонажем.
